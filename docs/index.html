Local PHP development.
Just files and folders.

Wharf runs PHP, nginx and Apache right on your computer — no Docker, no VM. Every folder is a project with a real address like my-kirby-site.localhost, HTTPS in one switch, and the PHP version it needs.

How it works

Three steps. No wizard.

  1. Pick a folder

    Every folder in www/ is a project. Any other folder can be added right where it lives — your code never moves.

  2. Start it from the tray

    Start, stop and open live in the tray menu. The window is there when you need it, not for a two-second action.

  3. Open a real URL

    Each project gets its own address, with HTTPS if you want it. Your computer finds it by itself: nothing to set up, no password, no port number in the address.

    https://my-kirby-site.localhost

Features

Everything a PHP project needs.
Nothing it doesn't.

  • Real addresses, no prompts

    Each project answers at <name>.localhost, which your computer knows by itself — Safari included. Adding a project never touches the hosts file or asks for a password.

  • HTTPS with one switch

    Turn it on and Wharf fetches mkcert, checks it, and makes a certificate. Your computer asks once to trust it. Say no, and the project still works.

  • The PHP you already have

    PHP versions on your computer are found and used where they are. Any supported version is one click to download, and each shows how long it still gets fixes.

  • One PHP version per project

    An old client site on PHP 8.2 next to a fresh one on 8.4 — set it in the project's settings. Everything else keeps the default.

  • nginx or Apache, per project

    Switch the webserver for everyone, or give one project the other one. Its address stays the same.

  • One php.ini for all

    memory_limit, upload sizes, display_errors: one file, read by every PHP version. Save it, and only PHP restarts.

  • Your own webserver settings

    A per-project .nginx.conf or .apache.conf, applied when you save. If the webserver refuses it, you see its own error with the file and line — right away.

  • Rules for your CMS

    Config templates for Kirby, Laravel, WordPress and more: pick one per project, edit it in Wharf, or save your own. Plain nginx and Apache syntax, nothing hidden.

  • Logs, one folder per project

    Requests and errors for each project — PHP's warnings included — land in data/log/projects/<name>/, one click away in its settings.

  • Kirby in one click

    “New project” fetches the Kirby starter kit and starts it. Pages, Panel and media just work, and content/ and site/ are never served as files.

  • Lives in your tray

    Start, stop, restart and open projects without opening a window. The tray and the window always show the same thing.

  • One application

    Launch Wharf and it works. Quit, and everything it started stops. Even if it crashes, nothing is left running behind your back.

  • Accessible by default

    Readable contrast in light and dark, status shown by shape as well as colour, every button labelled, and the keyboard reaches everything.

Under the hood

One front door on port 80.

One copy of the active webserver serves every project, each with its own generated config file. A project that uses the other webserver gets its own copy, reachable only from your computer, and the front door passes its requests through.

HTTPS ends at the front door, so it works the same either way. A name no project has is turned away, never answered by the wrong project.

The front door answers your computer only: nobody else on the network reaches your projects.

Kirby-inspired minimalism

What Wharf is not.

  • Not a container. No Docker, no VM — ordinary programs, so your files are as fast as your disk.
  • Not a dashboard. No charts, no onboarding carousel. One list of projects; details behind a click.
  • Not a database. Your whole setup is one JSON file you can edit by hand.
  • Not three different apps. It works the same on Windows, macOS and Linux.
  • Not a big first download. Wharf uses what you have and installs only when you ask.

FAQ

Questions, answered.

Does Wharf use Docker or a virtual machine?

No. PHP, nginx, Apache and mkcert run as ordinary programs on your computer. Nothing is put in a container and nothing is virtualised, so your files are as fast as your disk.

Will Wharf ask for my password?

Adding or creating a project never does. The one prompt comes the first time you turn on HTTPS: your computer has to be told once to trust Wharf's certificates. Saying no is fine — HTTPS stays on, browsers show a warning until you trust it, and Settings offers to ask again.

Why .localhost and not .test?

The name .localhost is reserved for your own computer (RFC 6761). macOS, Linux and every current browser answer it by themselves, so nothing is written to the hosts file. A made-up ending such as .test needs the hosts file instead, which macOS 26 does not reliably read.

Which PHP versions can I use?

Any version already on your computer is used where it is. Every version that still gets security fixes can be downloaded from Settings. The default is the newest version in active support, and each project can pick its own.

Do I have to move my projects into a special folder?

No. Any folder in www/ is a project, and a folder anywhere else can be added with “Add folder…” and stays where it is. Removing such a project never touches its files.

Can I use Wharf without the app?

The app is what runs Wharf, but you never have to click through it: the whole setup is one JSON file that Wharf picks up again when you edit it by hand.

Is Wharf only for Kirby?

No — any folder of PHP is a project. Kirby is the reference: its starter kit is one click away. Ready-made nginx and Apache rules for Kirby, Laravel, WordPress, Statamic, Symfony, Craft CMS and Drupal are built in, one pick per project.

What about MySQL, PostgreSQL, Node.js or Mailpit?

They are on the roadmap: how they will behave is written down, but they are deliberately not built yet. The first version does PHP, and does it well.

Can I install an older nginx or Apache for one project?

Not yet. Wharf has one version of nginx and one of Apache. When it installs one, it gets the newest version. Re-scan only looks for what is already on your computer — it does not check for updates.

Why: nginx and Apache do not offer ready-made downloads themselves, so Wharf gets them from somewhere else, and those places usually offer only the newest version. On a Mac, nginx comes from Homebrew, which has just the current version. On Linux, Apache comes from your system's package manager, which has just one version.

What works today: each project can use either nginx or Apache. So a project that needs Apache can run on Apache while all others run on nginx — and its address stays the same. Choosing a webserver version per project, as you already can for PHP, is planned wherever older versions are available to download.

Can I download Wharf?

Not yet — there are no installers. The desktop app runs on macOS today when built from source with make gui; see the README.
